Download

Every release is on the GitHub release page. For an installation you need:

FileWhat it is
systemLinux-0.2.5-x86_64.isoThe live system you boot to install from (about 650 MB).
systemLinux-0.2.5-x86_64.iso.sha256Its checksum.
systemLinux-stage-0.2.5-x86_64.tar.xzThe stage: the system you install. The live system downloads it for you in chapter 6; download it now only if the computer will have no network.
SHA256SUMSChecksums of every file in the release.
$ curl -LO https://github.com/tortr-rs/systemLinux/releases/download/v0.2.5/systemLinux-0.2.5-x86_64.iso
$ curl -LO https://github.com/tortr-rs/systemLinux/releases/download/v0.2.5/systemLinux-0.2.5-x86_64.iso.sha256

Check the download

A damaged download is the most common reason an ISO does not boot. Check it before you write it anywhere:

$ sha256sum -c systemLinux-0.2.5-x86_64.iso.sha256
systemLinux-0.2.5-x86_64.iso: OK

Anything other than OK means the file is damaged: download it again. On Windows, compare the output of certutil -hashfile systemLinux-0.2.5-x86_64.iso SHA256 with the .sha256 file by eye.

Write a USB stick

The ISO is a hybrid image: written byte for byte to a USB stick, it boots on UEFI and BIOS computers.

From Linux

$ lsblk                   # find the stick by its size, e.g. /dev/sdb; it must NOT be your system disk
$ sudo dd if=systemLinux-0.2.5-x86_64.iso of=/dev/sdX bs=4M status=progress conv=fsync

Use the whole stick (/dev/sdb), not a partition (/dev/sdb1). Everything on the stick is lost.

From Windows or macOS

Use Rufus (choose DD image mode when it asks) or balenaEtcher.

Ventoy

On a Ventoy stick, copy the ISO file onto it like any other file. The live system finds itself inside Ventoy, and several systemLinux ISOs on one stick do not mix up.

In a virtual machine

Attach the ISO as a CD and give the machine an empty disk of 20 GB or more. With QEMU:

$ qemu-img create -f qcow2 systemlinux.qcow2 40G
$ qemu-system-x86_64 -enable-kvm -cpu host -m 4G -smp 4 \
      -drive file=systemlinux.qcow2,if=virtio -cdrom systemLinux-0.2.5-x86_64.iso -nic user,model=virtio-net-pci

That boots in legacy BIOS mode. For UEFI add -drive if=pflash,format=raw,readonly=on,file=/usr/share/edk2/x64/OVMF_CODE.4m.fd (the path depends on your distribution's OVMF package). VirtualBox, VMware and GNOME Boxes work too; in VirtualBox, enable EFI in the machine's settings if you want a UEFI install.
