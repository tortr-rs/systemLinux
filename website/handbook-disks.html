Block devices

# lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS,MODEL

Disks are named after their connection: /dev/sda, /dev/sdb (SATA, USB), /dev/nvme0n1 (NVMe), /dev/vda (virtual machines), /dev/mmcblk0 (eMMC, SD cards). Partitions add a number: /dev/sda1, or p and a number on names ending in a digit: /dev/nvme0n1p1. Find the disk to install to by its size and model, and make sure it is not the stick you booted from.

Partition layouts

systemLinux uses a GPT partition table, which works with UEFI and legacy BIOS alike. The recommended layout:

PartitionSizeTypeMounted atWhy
11 MiBBIOS boot(none)GRUB's code on legacy BIOS. Harmless on UEFI: keep it, and the disk boots on both.
21 GiBEFI System/bootFAT32. Holds GRUB, the kernel and the initramfs. UEFI firmware reads it; GRUB reads it on BIOS too.
3the restLinux filesystem/The system and your files. Can be encrypted (LUKS), since nothing needed to start lives here.

Variants:

  • Separate /home: split partition 3 into a root partition of 40 GB or more and a /home partition, so you can reinstall without touching your files.
  • Swap partition: add one of 1–2 times your RAM if you want to hibernate; otherwise a swap file (below) or nothing. The system already uses compressed RAM swap (zram) by default.
  • Dual-boot: see below.

Partitioning

This erases the disk. Check the disk name once more with lsblk.

With cfdisk (menus)

# cfdisk /dev/sda

Choose gpt if it asks for a label type, then create the three partitions with New, setting each one's Type (BIOS boot, EFI System, Linux filesystem), and Write.

With sfdisk (one command)

# wipefs -a /dev/sda
# printf 'label: gpt\n,1M,21686148-6449-6E6F-744E-656564454649\n,1G,U\n,,L\n' | sfdisk /dev/sda

Each line after label: gpt is one partition: start (empty: next free), size, type. U is an EFI System Partition, L a Linux filesystem, and the long number is the BIOS boot type.

# lsblk /dev/sda          # three partitions: sda1, sda2, sda3

Encryption (optional)

To encrypt the root partition with LUKS, do this before formatting it. You type the passphrase at every boot, before the system starts; without it the data cannot be recovered, by design.

# cryptsetup luksFormat --type luks2 /dev/sda3
# cryptsetup open /dev/sda3 root

The opened partition is /dev/mapper/root: format and mount that one instead of /dev/sda3 in the rest of the installation. The name root matters: the initramfs opens it under the same name at boot.

Filesystems

# mkfs.vfat -F32 -n BOOT /dev/sda2
# mkfs.ext4 -L systemLinux /dev/sda3       # or /dev/mapper/root when encrypted

The live system formats ext4, the safe default. XFS and Btrfs work as the root filesystem too (the initramfs has their drivers), but their tools are not on the live ISO: install xfsprogs or btrfs-progs with get in the live system first if you want them.

Swap

A swap partition:

# mkswap /dev/sda4 && swapon /dev/sda4

A swap file is easier to resize later; make it after the stage is extracted (chapter 7).

Mounting the root filesystem

# mount /dev/sda3 /mnt       # or /dev/mapper/root

Only the root filesystem for now: the stage is extracted onto it in the next chapter, and the boot partition is mounted after that. A separate /home goes to /mnt/home after the stage is extracted.

Dual-boot next to another system

Make room in the other system first: shrink a partition with Windows Disk Management, GParted or resize2fs, and create a new empty partition of 20 GB or more. (XFS cannot shrink: back up, recreate it smaller, restore.) Then, in the live system:

  • Format only the new partition as the root filesystem and mount it on /mnt.
  • On UEFI, do not format the existing EFI System Partition: it holds the other system's bootloader. You will mount it at /boot/efi in the next chapter, and the kernel stays in /boot on the root filesystem.
  • Encrypting the root partition needs a separate unencrypted /boot partition (1 GiB, ext4 or FAT32) in this setup.
