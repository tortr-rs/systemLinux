dinit is the init system and service manager of systemLinux. It is the first program the kernel starts (PID 1), it starts and supervises every service, and it shuts the system down. There is no systemd: no systemctl, no journal, no logind.

Controlling services

dinitctl talks to the running dinit. Changing services needs root.

CommandWhat it does
dinitctl listevery loaded service and its state
dinitctl status NAMEstate, process id and last exit status of NAME
dinitctl start NAMEstart NAME and what it depends on
dinitctl stop NAMEstop NAME and what depends on it
dinitctl restart NAMEstop and start again
dinitctl enable NAMEstart NAME now and at every boot
dinitctl disable NAMEno longer start NAME at boot (and stop it)
dinitctl reload NAMEre-read NAME's service file
dinitctl setenv VAR=VALUEset an environment variable for services started from now on

In dinitctl list, [{+} ] means started, [ {-}] stopped, and [{ }<< ] starting.

Power

$ sudo poweroff
$ sudo reboot
$ sudo shutdown -h                       # same as poweroff

dinit stops every service in reverse dependency order, kills the remaining processes, turns off swap, unmounts the file systems and powers off.

Enabling services

The boot service is what dinit starts at boot. It waits for every service linked into /etc/dinit.d/boot.d/, so enabling a service is only a link there:

$ sudo dinitctl enable sshd               # on a running system
# ln -s ../sshd /etc/dinit.d/boot.d/sshd   # the same by hand (in a chroot, where dinit is not running)

early-filesystemsscriptedmounts /proc, /sys, /dev, /run, /dev/pts, /dev/shm, /tmp and the EFI variables

Ports add their own, for example seatd, greetd, chronyd, bluetoothd, cupsd and iwd. get install tells you when a port comes with a service.

Writing a service

A service is a small text file in /etc/dinit.d/, named after the service. A program that stays in the foreground:

# /etc/dinit.d/myapp
type = process
command = /usr/bin/myapp --no-daemon
depends-on = network
smooth-recovery = true

Then sudo dinitctl enable myapp. The most used settings:

type = process | bgprocess | scripted | internal
process: dinit runs and supervises the program, which must not fork into the background. scripted: a command that runs to completion (and an optional stop-command). internal: no program, only dependencies. bgprocess: a daemon that forks, with pid-file =.
command = ...
the program and its arguments, with an absolute path
depends-on = NAME
NAME must start first; if NAME stops, this service stops too
waits-for = NAME
start NAME first, but carry on even if it fails
depends-ms = NAME
like depends-on, but this service keeps running if NAME stops later
waits-for.d = DIR
waits for every service linked in DIR (how boot.d works)
restart = true | false
restart the process when it exits (default for process: true)
smooth-recovery = true
restart it without stopping the services that depend on it
logfile = /var/log/myapp.log
where the program's output goes (otherwise it is discarded)
run-as = USER
run the program as USER
env-file = /etc/myapp.env
environment variables, one VAR=VALUE per line

The full reference is man dinit-service on a system with man pages, or the online manual. Check a service file with dinit-check NAME.

User services

Every user can run their own dinit, which starts the services of their graphical session: the session D-Bus, PipeWire and WirePlumber. Start it from your window manager's configuration (exec dinit), see Graphical session.

PathContents
/etc/dinit.d/user/user services every user gets (installed by ports)
/etc/dinit.d/user/boot.d/those started with the session
~/.config/dinit.d/your own services; a boot there replaces the system's

Control them with dinitctl without sudo, from inside the session: dinitctl list, dinitctl restart pipewire.

Logs

There is no journal. Each long-running service writes its output to its own file, /var/log/NAME.log (the logfile setting): /var/log/NetworkManager.log, /var/log/dbus.log (with the programs D-Bus starts, such as ModemManager), /var/log/udevd.log, and so on. The kernel's messages are in dmesg.

With quiet on the kernel command line (the default GRUB entry), dinit only prints errors at boot, so the console stays clean and the login prompt appears on a cleared screen. Boot the entry without quiet ("show all boot messages") to see a line for every service as it starts.

Troubleshooting

  • A service failed at boot: dinitctl status NAME shows why; start it by hand with sudo dinitctl start NAME to see its messages.
  • "service description not found": the file is not in /etc/dinit.d, or its name is different from the name you typed.
  • The boot hangs on a service: boot with systemlinux.debug=1, or add init=/bin/bash to the kernel command line and remove the link from /etc/dinit.d/boot.d/ (see Recovery).
