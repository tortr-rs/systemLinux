Release 0.4

A Linux distribution built from scratch.

systemLinux pairs a custom monolithic kernel and its own init, systemL, with a Gentoo userland. It boots straight into RAM, in a minimal console edition or with a live XFCE desktop, and you can install it to disk when you want it to stay.

About systemLinux

A small system you can read end to end: one kernel config, one init written in Go, and a package tool that builds from upstream source.

Its own init

systemL runs as PID 1: it mounts the core filesystems, starts udev, D-Bus and NetworkManager, supervises them, and gives you a shell on tty1.

Runs from RAM

The whole system unpacks into memory at boot, so it is fast and leaves your disks untouched until you decide to install.

Two editions

Minimal boots to a root shell. XFCE boots straight into a live XFCE desktop.

Source-first packages

goget builds programs from GitHub, GitLab and Codeberg. For large software such as desktop environments, use emerge.

Tested on real hardware

Built with drivers for Lenovo IdeaPad and MSI machines, and run on bare metal rather than only in a virtual machine.

The systemLinux Handbook

Installing systemLinux from the live environment to an internal disk. From the XFCE edition, open a terminal in the desktop first; both editions install the same way.

Warning: this erases the target disk. Run every command as root from the live system. The examples use an NVMe drive (/dev/nvme0n1); for a SATA disk use /dev/sda with partitions /dev/sda1 and /dev/sda2.

1. Prepare the disk

Identify the target disk, then create a GPT layout with a 512MB EFI System Partition and a root partition.

# list block devices and confirm the target disk
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT

# destructive: wipes /dev/nvme0n1, creates p1 (ESP) and p2 (root)
sfdisk /dev/nvme0n1 <<'EOF'
label: gpt
,512M,U
,,L
EOF

2. Format the partitions

mkfs.vfat -F32 /dev/nvme0n1p1
mkfs.ext4 /dev/nvme0n1p2

3. Mount the target

Mount the root partition on a scratch path, then mount the EFI partition inside it.

mkdir -p /mnt/target
mount /dev/nvme0n1p2 /mnt/target

mkdir -p /mnt/target/boot/efi
mount /dev/nvme0n1p1 /mnt/target/boot/efi

4. Copy the system

Deep-copy the running system to the disk. -x keeps the copy on one filesystem, so the virtual filesystems stay out. Then recreate their mount points empty.

cp -ax / /mnt/target/

mkdir -p /mnt/target/proc /mnt/target/sys /mnt/target/dev /mnt/target/run /mnt/target/tmp
chmod 1777 /mnt/target/tmp

5. Write fstab

cat << 'EOF' > /mnt/target/etc/fstab
/dev/nvme0n1p2  /         ext4  errors=remount-ro  0  1
/dev/nvme0n1p1  /boot/efi vfat  defaults           0  2
EOF

6. Configure GRUB

The kernel has no initramfs, so give the root partition directly for it to mount. rootwait makes it wait for the NVMe drive to appear.

mkdir -p /mnt/target/boot/grub
cat << 'EOF' > /mnt/target/boot/grub/grub.cfg
set default=0
set timeout=3

menuentry "systemLinux v0.4 (Bare Metal)" {
    linux /boot/vmlinuz root=/dev/nvme0n1p2 rootwait rw console=tty0 init=/sbin/systemL quiet loglevel=3
    # if the device path does not mount, use root=PARTUUID=<your-root-partuuid>
}
EOF

7. Kernel and bootloader

Place the kernel on the permanent boot track and install GRUB to the drive.

cp /boot/vmlinuz /mnt/target/boot/vmlinuz

grub-install --target=x86_64-efi --efi-directory=/mnt/target/boot/efi \
  --boot-directory=/mnt/target/boot --removable

8. First user (optional)

Brand the install (/etc/issue, os-release, the login banner) and create a first user in wheel, portage and networkmanager with a sudo rule. It prompts for the password. With a user set up, create /etc/systemL/login so tty1 asks for a login instead of opening a root shell.

goget provision --user yourname /mnt/target
mkdir -p /mnt/target/etc/systemL
touch /mnt/target/etc/systemL/login

9. Finish and reboot

umount -R /mnt/target
reboot # remove the installation media on restart

Using systemL

systemL has no configuration to write for a normal boot. These commands control it at runtime (as root).

systemL statusList supervised services with state, PID, restarts and uptime
systemL start|stop|restart <service>Control a service (udevd, dbus, NetworkManager, or anything in services.conf)
reboot / poweroff / haltPower commands, also available as systemL reboot|poweroff|halt
/etc/systemL/loginIf this file exists, tty1 asks for a login instead of opening a root shell
/etc/systemL/services.confExtra daemons to supervise, one <name> <command> [args] per line
HostnameRead from /etc/hostname, defaulting to systemlinux
Logs/run/log/systemL/<name>.log

Known limitations

  • The live system runs from RAM: changes are lost on reboot until you install it to disk.
  • Boot in UEFI mode. Legacy BIOS boot freezes with the large initrd.
  • The live XFCE session runs as root and has no login manager. Shutdown and reboot from the XFCE menus do not work (there is no logind); run reboot or poweroff in a terminal.
  • The desktop comes from Debian packages layered onto the Gentoo userland. Software that needs more than that (for example a login manager or power management) is not included.
  • The kernel has Intel and legacy NVIDIA graphics built in, but no AMD driver, and the NVIDIA GeForce drivers are not included: X uses the generic display driver.
  • The old zram swap unit and Plymouth splash from v0.2 are not started by systemL. systemctl is still in the image but does nothing without systemd.
  • goget does not track installed packages or resolve dependencies. Use emerge for large packages.
