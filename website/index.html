Release 1.2

The computer belongs to the people who use it.

Your computer is a means of production, and tech companies rent it back to you. They decide what runs on it, they watch what you do, and they sell what they learn. systemLinux is a small GNU/Linux system that nobody owns and nobody profits from. Install it, read it, change it, give it away.

Why communist

We mean it literally. This is what it means for the code and for the people who use it.

No owners

No company, foundation or founder owns systemLinux. There's no trademark to license and no copyright assignment to sign. The copy you download is as much yours as anyone's.

No profit

No ads, no telemetry, no accounts, no premium tier. Big Tech makes its money turning your attention into someone else's profit. We don't sell anything, so there's nothing to sell you.

From each according to ability, to each according to need

Everyone gets the whole system, whether they contribute or not. Write code, test it on your hardware, translate, fix the docs, or just tell us what broke. Donations help, and they buy nothing: no say over the roadmap, no special treatment.

Decided in public

Decisions happen in the open repository, in issues and pull requests anyone can read and argue with. The people doing the work make the calls, and they answer to the people using it.

Against enclosure

Free software is a commons, and corporations keep fencing it off: open-core licences, cloud lock-in, "community editions" with the useful parts cut out. We build on the commons and give everything back to it. Nothing here will ever go behind a paywall.

Old hardware counts

A system that needs a new laptop is a system for people with money. systemLinux runs in about 3 GB of RAM, on machines companies have already written off. It only speaks English so far, and we need translators to change that.

What you get

A console system where the everyday things work. Try it live, install it, keep it updated.

Console first

No desktop comes bundled. You do get Bluetooth, PipeWire audio, chrony for the clock, power profiles, CUPS printing, fwupd firmware updates, Flatpak, and a firewall that blocks incoming connections by default.

Install it yourself

The handbook lists every command. If you'd rather not type them, systemlinux-install runs the same steps. Use a whole disk, or a partition you've already freed up. It boots from a USB stick or Ventoy, in UEFI mode.

Atomic updates

The system is a read-only image that gets replaced whole, like Fedora Silverblue. goget upgrade downloads a signed image and boots it once as a trial. If it doesn't come up, you're back on the old one. Your files and programs aren't touched.

Packages you can undo

goget install pulls signed, prebuilt software from nixpkgs into your own profile. Any change can be rolled back. You can run a program without installing it, or keep your whole setup in one text file.

Plain systemd

Services are ordinary systemd units. systemctl, journalctl and loginctl do what you already know they do.

Drivers built in

One kernel with Intel, AMD and open-source NVIDIA graphics, Wi-Fi, Bluetooth, storage and laptop drivers compiled in, plus the firmware they need.

goget

goget installs prebuilt, signed packages from the NixOS binary cache into /nix/store and gives each user a profile. You don't have to learn the Nix language or compile anything.

$ goget find editor
$ goget install htop git firefox
# downloaded, verified against the cache's signature, linked
$ goget run cowsay hello        # try it, install nothing
$ goget shell python3 nodejs     # a shell with those tools
$ goget generations
   1  htop
 * 2  htop git firefox
$ goget rollback                # undo the last change
$ goget gc                      # free what nothing uses
  • Every change can be undone. Each install, removal or update makes a new generation, and goget rollback switches back to the last one.
  • Your setup in a text file. Put package names in ~/.config/goget/packages, one per line, and run goget apply.
  • Checked before use. Every store path is verified against the cache’s ed25519 signature and its SHA-256. Packages never overwrite each other.
  • A profile for each user. Install without sudo. sudo goget install installs for the whole system.
  • Pick a channel. goget channel stable or unstable.
  • Also from source. goget install owner/repo builds from GitHub, GitLab or Codeberg.

Download

One live ISO you can write to a USB stick or drop onto a Ventoy drive. Boot in UEFI mode.

systemLinux

Boots to a root shell on the console. Install it by hand with the handbook, or run systemlinux-install. The ISO is about 1.9 GB and needs 3 GB of RAM (4 GB or more for copy to RAM).

systemlinux-v1.2.iso

SHA-256

Check your download with sha256sum systemlinux-v1.2.iso against the checksum on the releases page. Older versions are on the releases page; the source is on GitHub.

Ventoy: copy the ISO onto the stick. Older systemLinux ISOs on the same stick are fine: each ISO only boots its own system. If it reports an error at boot, write the ISO straight to a stick instead.

The systemLinux Handbook

From the downloaded ISO to an installed system that updates itself. Every command is written out.

Warning: installing erases whichever disk or partition you point it at. Back up first. UEFI only. Legacy BIOS boot is not supported.

1. Make a bootable USB stick

Download the ISO and check it against the SHA-256 on the release page. Then copy it onto a Ventoy stick, or write it straight to a stick (this erases the stick):

sudo dd if=systemlinux-v1.2.iso of=/dev/sdX bs=4M status=progress conv=fsync

Replace /dev/sdX with the stick (check with lsblk). On Windows use Rufus in DD image mode or balenaEtcher.

2. Boot the live system

Restart, open your firmware’s boot menu (usually F12, F10, Esc or F8) and pick the stick’s UEFI entry. The boot menu offers:

  • systemLinux: the normal live session, a root shell on the console.
  • copy to RAM: loads the whole system into memory so you can remove the stick.
  • debug shell: shows every message and stops just before the real system starts. Use it if the normal entry does not work.

Nothing is written to your disks until you follow chapter 3 or run systemlinux-install. Bring up networking first if you need it (nmcli device wifi connect <ssid> password <pass>, or plug in Ethernet).

3. Install to disk, by hand

This is the whole install, one real command at a time. $DISK is a whole disk (e.g. /dev/sda, /dev/nvme0n1); for a dual-boot install into a partition you already freed with GParted or Windows Disk Management, skip straight to the existing partition note under step 2.

Step 1: pick the disk and wipe it

$ lsblk                                 # find your disk; be sure before the next line
$ DISK=/dev/sda
$ wipefs -a -f "$DISK"
$ dd if=/dev/zero of="$DISK" bs=1M count=4

Step 2: partition and format

GPT with a 512 MiB EFI System Partition and one ext4 partition for everything else (system images, GRUB and your files):

$ printf 'label: gpt\n,512M,U\n,,L\n' | sfdisk --wipe always --wipe-partitions always "$DISK"
$ mkfs.vfat -F32 -n EFI "${DISK}1"        # nvme/mmc disks: ${DISK}p1
$ mkfs.ext4 -F -q -L systemLinux "${DISK}2"

Existing partition instead of a whole disk: if you pre-shrank another OS and have a free partition already, set DATADEV=/dev/sdXN to that partition, run only the mkfs.ext4 line above against it, and reuse your existing EFI System Partition (skip the mkfs.vfat line and the whole-disk wipefs/dd in step 1). Then substitute $DATADEV for ${DISK}2 and your existing ESP for ${DISK}1 in every step below.

Step 3: copy the system

$ VER=$(cat /usr/share/systemlinux/image-version)
$ mkdir -p /mnt/target-data /mnt/target-sq /mnt/target-root
$ mount "${DISK}2" /mnt/target-data
$ mkdir -p /mnt/target-data/boot/images/$VER /mnt/target-data/persist/upper \
           /mnt/target-data/persist/work /mnt/target-data/boot/efi
$ mount "${DISK}1" /mnt/target-data/boot/efi
$ cp /live-medium/live/vmlinuz /live-medium/live/initrd.img /live-medium/live/rootfs.squashfs \
      /mnt/target-data/boot/images/$VER/

Mount the copied image with a persistent overlay, so the next steps write into the real installed root:

$ mount -t squashfs -o loop,ro /mnt/target-data/boot/images/$VER/rootfs.squashfs /mnt/target-sq
$ mount -t overlay overlay -o lowerdir=/mnt/target-sq,upperdir=/mnt/target-data/persist/upper,workdir=/mnt/target-data/persist/work /mnt/target-root

Step 4: basic settings and accounts

$ ROOT=/mnt/target-root
$ ESPUUID=$(blkid -s UUID -o value "${DISK}1")
$ printf '/data/boot  /boot  none  bind  0 0\nUUID=%s  /boot/efi  vfat  umask=0077  0  2\n' "$ESPUUID" > "$ROOT/etc/fstab"
$ echo myhostname > "$ROOT/etc/hostname"
$ ln -sf ../usr/share/zoneinfo/Region/City "$ROOT/etc/localtime"   # e.g. Europe/Lisbon
$ echo LANG=C.UTF-8 > "$ROOT/etc/locale.conf"
$ goget provision --user yourname "$ROOT"    # prompts for your password, creates the account, sudoers, branding
$ rm -rf "$ROOT/etc/systemd/system/getty@tty1.service.d"   # ask for a login on tty1 (the live image logs root in)
$ chpasswd -R "$ROOT"                         # set the root password, "root:yourpassword"

Step 5: install GRUB

$ grub-install --target=x86_64-efi --efi-directory=/mnt/target-data/boot/efi \
    --boot-directory=/mnt/target-data/boot --removable
$ PARTNUM=1
$ efibootmgr -c -d "$DISK" -p "$PARTNUM" -L systemLinux -l '\EFI\BOOT\BOOTX64.EFI'   # best-effort; fine to fail without efivars
$ DUUID=$(blkid -s UUID -o value "${DISK}2")
$ systemlinux-grubcfg /mnt/target-data/boot "$DUUID"
$ grub-editenv /mnt/target-data/boot/grub/grubenv create
$ grub-set-default --boot-directory=/mnt/target-data/boot "$VER"

Restart and remove the stick. That’s the whole install. Nothing else runs behind your back.

4. Optional: encrypt with LUKS

To encrypt the data partition, do this before step 2’s mkfs.ext4 in chapter 3:

$ cryptsetup luksFormat "${DISK}2"
$ cryptsetup luksOpen "${DISK}2" systemlinux-data
$ mkfs.ext4 -F -q -L systemLinux /dev/mapper/systemlinux-data

Then use /dev/mapper/systemlinux-data everywhere chapter 3 says ${DISK}2 (mounting, blkid for the data UUID, and so on). At boot, the live initramfs recognises a LUKS data partition from its UUID and prompts for the passphrase before mounting it. There’s nothing extra to configure. Keep the passphrase somewhere safe: there is no recovery without it.

5. The fast path: systemlinux-install

Everything in chapters 3–4, asked as plain questions instead of typed by hand:

$ sudo systemlinux-install

It prompts for a whole disk or an existing partition, hostname, username and password, time zone, keyboard layout, and whether to encrypt with LUKS, then runs exactly the steps above. Nothing happens until you confirm the summary it shows first.

6. First boot

GRUB shows for three seconds, then systemLinux starts to a console login. Your user can use sudo.

7. Installing software

Use goget. Programs go into your own profile, so no sudo is needed:

$ goget find video
$ goget install vlc gimp
$ goget list
$ goget remove gimp
$ goget update                   # newer versions of what you installed
$ goget run neofetch            # run without installing

Prefer a list? Write package names, one per line, to ~/.config/goget/packages and run goget apply: the profile then matches the file exactly. Every change is a generation, so goget rollback undoes it, and goget gc deletes what nothing uses.

8. Updating the system

The system itself updates as a whole image, so an update cannot leave it half-upgraded:

$ goget upgrade --check    # is a newer image available?
$ sudo goget upgrade       # download, verify and install it

The image is downloaded (a broken download resumes), verified against a signed release index and its SHA-256 hashes, and added to the boot menu as a one-time trial. Restart to use it. Your files, accounts, settings and installed programs are not touched.

9. Rolling back

The first boot into a new system image is a trial. If it does not come up, the next boot returns to the previous image automatically. Once the new system has run for a minute, systemlinux-boot-good.timer makes it the default. The previous image stays installed and you can pick it by hand in the GRUB menu at startup. Programs installed with goget roll back separately with goget rollback.

10. Recovery

Boot an older image: at the GRUB menu, pick a previous version. Every image goget upgrade hasn’t cleaned up yet stays listed and bootable.

Repair a broken install from the live ISO: boot the live medium, then mount and chroot into the installed system the same way the installer assembles it:

$ mkdir -p /mnt/data /mnt/sq /mnt/root
$ mount /dev/sdXN /mnt/data                          # the data partition
$ VER=$(ls /mnt/data/boot/images | sort | tail -1)   # or the version you want to fix
$ mount -t squashfs -o loop,ro /mnt/data/boot/images/$VER/rootfs.squashfs /mnt/sq
$ mount -t overlay overlay -o lowerdir=/mnt/sq,upperdir=/mnt/data/persist/upper,workdir=/mnt/data/persist/work /mnt/root
$ mount --bind /mnt/data /mnt/root/data
$ mount --bind /proc /mnt/root/proc && mount --bind /sys /mnt/root/sys && mount --bind /dev /mnt/root/dev
$ chroot /mnt/root /bin/bash

Fix what needs fixing (reset a password with passwd, edit /etc/fstab, reinstall GRUB with the same command as chapter 3 step 5), then exit and unmount in reverse order before rebooting.

Back up: everything you can lose lives under /persist/upper on the data partition. That’s the entire writable layer (your files, accounts, and any changes made outside of goget profiles). Copy it (or just /home and /etc within it) to external storage regularly; system images themselves are always re-downloadable and never need backing up.

11. If something goes wrong

  • The stick does not boot: choose the UEFI entry, write the ISO with dd instead of Ventoy, and check the checksum.
  • No console after boot: use the debug shell entry, or remove quiet from the kernel command line to see systemd’s boot messages on screen. From a running system, journalctl -b and systemctl --failed.
  • No Wi-Fi: a device whose firmware is not in the bundled set will not start. A USB tether or Ethernet always works.
  • Wrong partition wiped: double-check lsblk output before every wipefs/sfdisk command. There’s no undo. That’s why chapter 3 is written out by hand: read each command before you run it.
  • LUKS passphrase not accepted at boot: the live/installed initramfs asks again on the next attempt; a truly lost passphrase means the data partition is unrecoverable by design.
  • An installed system fails to boot: pick the previous image from the GRUB menu, or the debug entry to see messages.

Services

systemd starts everything; there is nothing to configure for a normal boot. The usual tools control it (as root).

systemctl status [unit]What is running, and what failed (systemctl --failed)
journalctl -b [-u unit]This boot’s log, or one service’s
systemctl start|stop|restart <unit>Control a service: NetworkManager, bluetooth, audio, cups, chronyd, nftables, …
systemctl list-timersgoget-check (looks for a new image every 12h, never installs by itself) and systemlinux-boot-good (makes a trial image the default)
reboot / poweroff / haltPower commands
/etc/systemd/system/The base image’s own units; add yours here and systemctl enable them
ConsoleThe live ISO logs root in on tty1; an installed system asks for a login. Add console=ttyS0 to the kernel command line for a serial login
HostnameRead from /etc/hostname (systemlinux on the live ISO)

What doesn't work yet

Known gaps. If one of these gets in your way, open an issue, or better, help fix it.

  • UEFI only: legacy BIOS boot is not supported.
  • No automatic partition resizing: dual-boot means shrinking Windows or another Linux yourself first, then installing into the freed partition.
  • No Secure Boot yet. LUKS full-disk encryption is available (chapter 4 of the handbook).
  • There’s no graphical login or lock screen. It’s a console system: you log in on tty1.
  • Only English is included. Suspend and lid handling depend on your hardware.
  • Programs from nixpkgs that need hardware-accelerated OpenGL or Vulkan can fall back to software rendering, because they carry their own graphics libraries.
  • The kernel has Intel, AMD and the open NVIDIA (nouveau) graphics drivers, not NVIDIA’s proprietary driver.
  • Atomic, but not sealed: the system image is read-only and swapped as a whole, but changes you make to /etc or /usr yourself are kept in a separate writable layer on top of it (unlike Silverblue’s strictly immutable root).
