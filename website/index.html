Release 1.0

A Linux you can live in — and undo.

systemLinux is an independent GNU/Linux distribution: its own init, a polished GNOME desktop, a graphical installer, and a package manager where every change — a system update or one installed app — can be rolled back.

Everything a daily system needs

Boot it live, try it, install it, and keep it up to date without fear.

A real desktop

GNOME 48 on Wayland with Firefox, Files, Terminal and Settings, audio through PipeWire, Bluetooth, Wi-Fi and power profiles.

Installs like any distro

A native graphical installer: pick a disk, set up your account, go. Boots in UEFI mode from a USB stick or Ventoy.

Updates that can’t brick it

goget upgrade downloads a signed system image, boots it as a trial and falls back to the old one by itself if it fails. Your files stay.

Packages with an undo button

goget install gives you prebuilt, signed nixpkgs software in your own profile. Roll back any change, run a program without installing it, keep a plain list of what you use.

Its own init

systemL is a small Go init that supervises services, keeps its logs out of your way and shuts down cleanly.

Wide hardware support

One monolithic kernel with Intel, AMD and open NVIDIA graphics, Wi-Fi, Bluetooth, storage and laptop drivers built in, plus firmware.

goget: packages the Nix way, in plain words

goget installs the prebuilt, cryptographically signed packages of the NixOS binary cache into /nix/store and shows them to you through profiles. It is not the Nix tool: there is no language to learn and nothing to compile, just short commands.

$ goget find editor
$ goget install htop git firefox
# downloaded, verified against the cache's signature, linked
$ goget run cowsay hello        # try it, install nothing
$ goget shell python3 nodejs     # a shell with those tools
$ goget generations
   1  htop
 * 2  htop git firefox
$ goget rollback                # undo the last change
$ goget gc                      # free what nothing uses
  • Everything can be undone. Each install, removal or update makes a new generation; goget rollback switches back instantly.
  • Declarative, without the syntax. Put package names in ~/.config/goget/packages, one per line, and run goget apply.
  • Safe by construction. Every store path is checked against the cache’s ed25519 signature and its SHA-256, and packages never overwrite each other.
  • Each user has a profile. Install without sudo; sudo goget install adds to the whole system.
  • Stable or bleeding edge. goget channel stable or unstable.
  • Also from source. goget install owner/repo builds from GitHub, GitLab or Codeberg.

1. Make a bootable USB stick

Download the GNOME ISO and check it against the SHA-256 above. Then copy it onto a Ventoy stick, or write it straight to a stick (this erases the stick):

sudo dd if=systemlinux-v1.0-gnome.iso of=/dev/sdX bs=4M status=progress conv=fsync

Replace /dev/sdX with the stick (check with lsblk). On Windows use Rufus in DD image mode or balenaEtcher.

2. Boot the live system

Restart, open your firmware’s boot menu (usually F12, F10, Esc or F8) and pick the stick’s UEFI entry. The boot menu offers:

  • systemLinux: the normal live session.
  • copy to RAM: loads the whole system into memory so you can remove the stick.
  • debug shell: shows every message and stops just before the real system starts. Use it if the normal entry does not work.

The live session signs in as live and opens GNOME with Firefox, Files and Terminal. Connect to Wi-Fi from the top bar. Nothing is written to your disks until you run the installer.

3. Install to disk

Open Install systemLinux from the dock (the cat icon). It walks through six pages:

  1. Welcome: what is about to happen.
  2. Disk: pick the disk to erase.
  3. Account: computer name, your name, user name and password, and whether to sign in automatically. The same password is used for root.
  4. Region: time zone and keyboard layout.
  5. Summary: review everything. Nothing has changed yet; Install starts the work.
  6. Progress: partitions the disk, copies the system, creates your account and installs the boot loader.

The disk gets a 512 MB EFI partition and one ext4 partition holding the system image, the boot menu and your files. When it says Done, restart and remove the stick.

4. First boot

GRUB shows for three seconds, then systemLinux starts. With automatic sign-in you land on the GNOME desktop; otherwise you sign in on the text console and GNOME starts for your user. Your user can use sudo.

5. Installing software

Use goget. Programs go into your own profile, so no sudo is needed:

$ goget find video
$ goget install vlc gimp
$ goget list
$ goget remove gimp
$ goget update                   # newer versions of what you installed
$ goget run neofetch            # run without installing

Prefer a list? Write package names, one per line, to ~/.config/goget/packages and run goget apply: the profile then matches the file exactly. Every change is a generation, so goget rollback undoes it, and goget gc deletes what nothing uses. Apps you install show up in the GNOME overview.

6. Updating the system

The system itself updates as a whole image, so an update cannot leave it half-upgraded:

$ goget upgrade --check    # is a newer image available?
$ sudo goget upgrade       # download, verify and install it

The image is downloaded (a broken download resumes), verified against a signed release index and its SHA-256 hashes, and added to the boot menu. Restart to use it. Your files, accounts, settings and installed programs are not touched.

7. Rolling back

The first boot into a new system image is a trial. If it does not come up, the next boot returns to the previous image automatically. Once the new system has run for a minute it becomes the default. The previous image stays installed and you can pick it by hand in the GRUB menu at startup. Programs installed with goget roll back separately with goget rollback.

8. If something goes wrong

  • The stick does not boot: choose the UEFI entry, write the ISO with dd instead of Ventoy, and check the checksum.
  • Black screen or no desktop: use the debug shell entry. From a text console (Ctrl+Alt+F2) read systemL’s log with systemL log.
  • No Wi-Fi: a device whose firmware is not in the bundled set will not start. A USB tether or Ethernet always works.
  • An installed system fails to boot: pick the previous image from the GRUB menu, or the debug entry to see messages.

Using systemL

systemL has no configuration to write for a normal boot. These commands control it at runtime (as root).

systemL statusList supervised services with state, PID, restarts and uptime
systemL log [service]Show systemL’s own log, or a service’s. systemL prints nothing to the terminal; add systeml.verbose=1 to the kernel command line to see its messages on screen
systemL start|stop|restart <service>Control a service (udevd, dbus, NetworkManager, or anything in services.conf)
reboot / poweroff / haltPower commands, also available as systemL reboot|poweroff|halt
/etc/systemL/loginIf this file exists, tty1 asks for a login instead of opening a root shell
/etc/systemL/services.confExtra daemons to supervise, one <name> <command> [args] per line
HostnameRead from /etc/hostname, defaulting to systemlinux
Logs/run/log/systemL/<name>.log

Honest limits

What 1.0 does not do yet, so nothing surprises you.

  • UEFI only, and the installer erases a whole disk: no dual boot or resizing yet, and no disk encryption or Secure Boot.
  • There is no login screen or lock screen: GNOME starts from the text console login (with optional auto-login).
  • Only English is included. Suspend and lid handling depend on your hardware.
  • Programs from nixpkgs that need hardware-accelerated OpenGL or Vulkan can fall back to software rendering, because they carry their own graphics libraries.
  • The kernel has Intel, AMD and the open NVIDIA (nouveau) graphics drivers, not NVIDIA’s proprietary driver.
  • systemL replaces systemd, so software that expects systemd services will not find them.
