Release 0.5

A Linux distribution built from scratch.

systemLinux is a GNU/Linux distribution: a custom monolithic kernel and its own init, systemL, with a GNU userland (GNU bash, coreutils, tar and more) on a Gentoo base. It boots like any live ISO, in a minimal console edition or with a live GNOME desktop, and you can install it to disk when you want it to stay. Installed systems update themselves with goget upgrade: a new signed system image replaces the old one at the next reboot, your files and settings stay, and a bad update rolls back by itself.

About systemLinux

A small system you can read end to end: one kernel config, one init written in Go, and a package tool that builds from upstream source.

Its own init

systemL runs as PID 1: it mounts the core filesystems, starts udev, D-Bus and NetworkManager, supervises them, and gives you a shell on tty1.

A real live ISO

The system is a compressed image on the ISO with a writable RAM layer on top. Only your changes use memory, and your disks are untouched until you choose to install.

Two editions

GNOME boots straight into a live desktop with Firefox and a graphical installer. Minimal boots to a root shell.

Drivers for almost everything

One kernel with Wi-Fi, Bluetooth, graphics (Intel, AMD, NVIDIA open driver), storage, sound and laptop drivers built in, and the firmware to go with them.

Source-first packages

goget builds programs from GitHub, GitLab and Codeberg. For large software such as desktop environments, use emerge.

Tested on real hardware

Built with drivers for Lenovo IdeaPad and MSI machines, and run on bare metal rather than only in a virtual machine.

The systemLinux Handbook

From a downloaded ISO to an installed, self-updating system. The GNOME edition includes a graphical installer, so there is nothing to type.

Warning: the installer erases the whole disk you choose. Back up first. Boot in UEFI mode.

1. Make a bootable USB stick

Download the GNOME ISO and check it against the SHA-256 shown above. Then either copy the ISO onto a Ventoy stick, or write it straight to a stick (this erases the stick):

sudo dd if=systemlinux-v0.5-gnome.iso of=/dev/sdX bs=4M status=progress conv=fsync

Replace /dev/sdX with the stick (check with lsblk). On Windows, use Rufus in DD image mode or balenaEtcher.

2. Boot the live system

Restart, open your firmware’s boot menu (usually F12, F10, Esc or F8) and pick the stick in its UEFI entry. The boot menu offers three choices:

  • systemLinux: the normal live session.
  • copy to RAM: loads the whole system into memory so you can remove the stick. Needs about 2 GB more RAM.
  • debug shell: shows every message and stops just before the real system starts. Use it if the normal entry does not work.

The live session signs in as live and opens the GNOME desktop with Firefox, Files and Terminal. Connect to Wi-Fi from the network icon in the top bar. Nothing is written to your disks until you run the installer.

3. Install to disk

Open Install systemLinux from the dock (the cat icon). The installer walks through six pages:

  1. Welcome: what is about to happen.
  2. Disk: pick the disk to erase. Disks that are in use by the live system are not offered.
  3. Account: computer name, your name, user name and password, and whether to sign in automatically. The same password is used for root.
  4. Region: time zone and keyboard layout.
  5. Summary: review everything. Nothing has been changed yet; Install starts the work.
  6. Progress: partitions the disk, copies the system, creates your account and installs the boot loader, with each step listed.

The disk gets a 512 MB EFI partition and one ext4 partition that holds the system image, the boot menu and your files. When it says Done, restart and remove the USB stick.

4. First boot

GRUB shows for three seconds, then systemLinux starts. With automatic sign-in on, you land directly on the GNOME desktop; otherwise you sign in on the text console and GNOME starts for your user. Your user can use sudo. Software comes from goget (programs from GitHub, GitLab or Codeberg, built or prebuilt) and emerge for large packages; everything you install is kept across updates.

5. Updating

systemLinux updates as a whole system image, so an update cannot leave the system half-upgraded:

goget upgrade --check     # is a newer image available?
sudo goget upgrade        # download, verify and install it

The image is downloaded (a broken download resumes), verified against a signed release index and its SHA-256 hashes, and added to the boot menu. Restart to use it. Your files, accounts, settings and installed programs are not touched.

6. Rolling back

The first boot into a new image is a trial. If it does not come up, the next boot returns to the previous image automatically. Once the new system has run for a minute it becomes the default. The previous image stays installed, and you can pick it by hand from the GRUB menu in the menu that GRUB shows for a few seconds at startup. Only the running image and the newest one are kept, to save space.

7. If something goes wrong

  • The stick does not boot: choose the UEFI entry, not the plain one; write the ISO with dd instead of Ventoy; check the checksum.
  • Black screen or no desktop: use the debug shell entry and note the last messages. Read systemL’s log with systemL log (or systemL log polkitd for one service) from a text console (Ctrl+Alt+F2).
  • No Wi-Fi: the kernel carries most drivers, but a device whose firmware is not in the bundled set will not start. A USB tether or Ethernet works everywhere.
  • Boot in an installed system fails: pick the previous image from the GRUB menu, or the debug entry to see messages.

Using systemL

systemL has no configuration to write for a normal boot. These commands control it at runtime (as root).

systemL statusList supervised services with state, PID, restarts and uptime
systemL log [service]Show systemL’s own log, or a service’s. systemL prints nothing to the terminal; add systeml.verbose=1 to the kernel command line to see its messages on screen
systemL start|stop|restart <service>Control a service (udevd, dbus, NetworkManager, or anything in services.conf)
reboot / poweroff / haltPower commands, also available as systemL reboot|poweroff|halt
/etc/systemL/loginIf this file exists, tty1 asks for a login instead of opening a root shell
/etc/systemL/services.confExtra daemons to supervise, one <name> <command> [args] per line
HostnameRead from /etc/hostname, defaulting to systemlinux
Logs/run/log/systemL/<name>.log

Updates

An installed systemLinux boots a read-only system image with your changes stored in a separate persistent layer, so updating means swapping the image.

goget upgrade --check    # is a newer image available?
sudo goget upgrade       # download, verify, install; then reboot

The new image is downloaded (resumable), checked against a signed index and its SHA-256 hashes, and added to the boot menu. The first boot into it is a trial: if it does not come up, the next boot returns to the previous image on its own. After the new system has run for a minute it becomes the default. Your files, accounts and settings are untouched, and only the running and the new image are kept on disk.

Known limitations

  • The live system keeps your changes only in RAM, so they are lost on reboot until you install it to disk. An installed system keeps them.
  • Shutdown, suspend and audio from the GNOME menus are not finished yet; poweroff and reboot in a terminal always work. Bluetooth is not included.
  • Boot in UEFI mode. Legacy BIOS boot has not been tested with the current live layout.
  • The graphical installer erases a whole disk. It cannot resize partitions or set up dual boot yet.
  • GNOME runs under elogind and polkit rather than systemd, so anything that expects systemd may not work; it starts from the login on the first text console (tty1).
  • The desktop comes from Debian packages layered onto the Gentoo userland. Software that needs more than that (for example a login manager or power management) is not included.
  • The kernel includes Intel, AMD and the open NVIDIA (nouveau) graphics drivers, but not NVIDIA’s proprietary driver. Drivers whose firmware is missing from the bundled set will not start.
  • The old zram swap unit and Plymouth splash from v0.2 are not started by systemL. systemctl is still in the image but does nothing without systemd.
  • goget does not track installed packages or resolve dependencies. Use emerge for large packages.
