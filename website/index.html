What “communist” means here

Not a slogan: a set of commitments about who owns the system and who it serves.

Common ownership

The system is a commons. No company owns systemLinux, and nobody can sell it to you, put it behind a paywall or lock you out of it. Anyone may use, study, change and share it.

No profit motive

No advertising, no telemetry, no accounts, no paid tiers and no data collected about you. Your attention and your data are not the product, because there is no product to sell.

From each according to ability, to each according to need

Everyone gets the same complete system, whether they can contribute or not. People give what they can: code, testing, translations, documentation, bug reports, money or time. Donations are voluntary and never buy influence.

Democratic control

Decisions are made in the open, where everyone affected can see and challenge them: in the public source repository, in issues and in pull requests, not behind closed doors. Whoever does the work has a say in it.

You control your machine

Updates are signed and roll back if they fail, nothing is installed without you, and you can inspect and change every part. The owner of a computer is the person who uses it.

Open to everyone

A barrier of language, hardware or money is a barrier to ownership. systemLinux runs on old and new machines, is free of charge, and needs translators: only English is included today, and that is a gap we want closed.

Everything a daily system needs

Boot it live, try it, install it by hand or with one script, and keep it up to date without fear.

A real console system

One minimal image: Bluetooth (bluez), audio (PipeWire), time sync (chrony), power profiles, CUPS printing, firmware updates (fwupd) and Flatpak, with a default firewall — everyday daemons, no bundled desktop.

Installs like you mean it

A real handbook with the exact commands, or the systemlinux-install script for the same steps automated. Whole-disk, or into a partition you freed yourself — your call. Boots in UEFI mode from a USB stick or Ventoy.

Atomic, like Silverblue

The system is a read-only image that is replaced as a whole, never patched file by file. goget upgrade downloads a signed image, boots it as a trial and falls back to the old one by itself if it fails. Your files and programs stay.

Packages with an undo button

goget install gives you prebuilt, signed nixpkgs software in your own profile. Roll back any change, run a program without installing it, keep a plain list of what you use.

Its own init

lenine is a small Go init that supervises services (with dependencies and cgroup limits), runs timers, and shuts down cleanly.

Wide hardware support

One monolithic kernel with Intel, AMD and open NVIDIA graphics, Wi-Fi, Bluetooth, storage and laptop drivers built in, plus firmware.

goget: packages the Nix way, in plain words

goget installs the prebuilt, cryptographically signed packages of the NixOS binary cache into /nix/store and shows them to you through profiles. It is not the Nix tool: there is no language to learn and nothing to compile, just short commands.

$ goget find editor
$ goget install htop git firefox
# downloaded, verified against the cache's signature, linked
$ goget run cowsay hello        # try it, install nothing
$ goget shell python3 nodejs     # a shell with those tools
$ goget generations
   1  htop
 * 2  htop git firefox
$ goget rollback                # undo the last change
$ goget gc                      # free what nothing uses
  • Everything can be undone. Each install, removal or update makes a new generation; goget rollback switches back instantly.
  • Declarative, without the syntax. Put package names in ~/.config/goget/packages, one per line, and run goget apply.
  • Safe by construction. Every store path is checked against the cache’s ed25519 signature and its SHA-256, and packages never overwrite each other.
  • Each user has a profile. Install without sudo; sudo goget install adds to the whole system.
  • Stable or bleeding edge. goget channel stable or unstable.
  • Also from source. goget install owner/repo builds from GitHub, GitLab or Codeberg.

What is in the image

KernelLinux 7.2.6, monolithic, with drivers for almost everything built in (Wi-Fi, Bluetooth, Intel/AMD/open NVIDIA graphics, storage, sound, laptop hardware, exFAT/NTFS/btrfs/XFS) and bundled firmware
Initlenine, a static Go binary running as PID 1: service dependencies, per-service cgroup limits, timers. No systemd
ServicesBluetooth (bluez), audio (PipeWire), time sync (chrony), power profiles, CUPS printing, fwupd, Flatpak, a default firewall (nftables) — no bundled desktop
UserlandGNU bash 5.3 as /bin/sh, GNU coreutils, tar, sed and gawk on glibc
Packagesgoget with nixpkgs (25.05 stable or unstable): store paths, profiles, generations, rollback
UpdatesAtomic, image-based, like Fedora Silverblue: signed system images (goget upgrade), trial boot and automatic rollback
InstallerNo GUI: a real handbook with the exact commands, plus systemlinux-install, a plain terminal script that automates the same steps — whole-disk or into an existing partition, with optional LUKS encryption
BootGRUB 2.12, UEFI x86_64 only. Live entries: normal, copy to RAM, debug shell
MemoryAbout 3 GB; the “copy to RAM” entry needs the whole 2.4 GB image in memory on top

Download

One live ISO you can write to a USB stick or drop onto a Ventoy drive. Boot in UEFI mode.

systemLinux

Boots to a root shell on the console: install it by hand from the handbook, or run systemlinux-install. About 2.4 GB, 3 GB of RAM (4 GB+ to use copy to RAM).

Get it from the releases page

Not a direct GitHub release asset: at 2.4 GB the ISO is over GitHub's 2 GB release-asset limit (it bundles the full upstream firmware set, not yet trimmed to just this kernel's drivers — see the roadmap). The release notes link to wherever it's actually hosted.

SHA-256
Published with each release on the releases page, alongside the signed update index — verify it there before trusting a download from anywhere else.

Check your download with sha256sum systemlinux-v1.1.iso against the checksum on the releases page. Older versions are on the releases page; the source is on GitHub.

Ventoy: copy the ISO onto the stick. Older systemLinux ISOs on the same stick are fine: each ISO only boots its own system. If it reports an error at boot, write the ISO straight to a stick instead.

The systemLinux Handbook

From a downloaded ISO to an installed, self-updating system — every command, not a wizard.

1. Make a bootable USB stick

Download the ISO and check it against the SHA-256 on the releases page. Then copy it onto a Ventoy stick, or write it straight to a stick (this erases the stick):

sudo dd if=systemlinux-v1.1.iso of=/dev/sdX bs=4M status=progress conv=fsync

Replace /dev/sdX with the stick (check with lsblk). On Windows use Rufus in DD image mode or balenaEtcher.

2. Boot the live system

Restart, open your firmware’s boot menu (usually F12, F10, Esc or F8) and pick the stick’s UEFI entry. The boot menu offers:

  • systemLinux: the normal live session, a root shell on the console.
  • copy to RAM: loads the whole system into memory so you can remove the stick.
  • debug shell: shows every message and stops just before the real system starts. Use it if the normal entry does not work.

Nothing is written to your disks until you follow chapter 3 or run systemlinux-install. Bring up networking first if you need it (nmcli device wifi connect <ssid> password <pass>, or plug in Ethernet).

3. Install to disk, by hand

This is the whole install, one real command at a time. $DISK is a whole disk (e.g. /dev/sda, /dev/nvme0n1); for a dual-boot install into a partition you already freed with GParted or Windows Disk Management, skip straight to the existing partition note under step 2.

Step 1: pick the disk and wipe it

$ lsblk                                 # find your disk; be sure before the next line
$ DISK=/dev/sda
$ wipefs -a -f "$DISK"
$ dd if=/dev/zero of="$DISK" bs=1M count=4

Step 2: partition and format

GPT with a 512 MiB EFI System Partition and one ext4 partition for everything else — system images, GRUB and your files:

$ printf 'label: gpt\n,512M,U\n,,L\n' | sfdisk --wipe always --wipe-partitions always "$DISK"
$ mkfs.vfat -F32 -n EFI "${DISK}1"        # nvme/mmc disks: ${DISK}p1
$ mkfs.ext4 -F -q -L systemLinux "${DISK}2"

Existing partition instead of a whole disk: if you pre-shrank another OS and have a free partition already, set DATADEV=/dev/sdXN to that partition, run only the mkfs.ext4 line above against it, and reuse your existing EFI System Partition (skip the mkfs.vfat line and the whole-disk wipefs/dd in step 1) — then substitute $DATADEV for ${DISK}2 and your existing ESP for ${DISK}1 in every step below.

Step 3: copy the system

$ VER=$(cat /usr/share/systemlinux/image-version)
$ mkdir -p /mnt/target-data /mnt/target-sq /mnt/target-root
$ mount "${DISK}2" /mnt/target-data
$ mkdir -p /mnt/target-data/boot/images/$VER /mnt/target-data/persist/upper \
           /mnt/target-data/persist/work /mnt/target-data/boot/efi
$ mount "${DISK}1" /mnt/target-data/boot/efi
$ cp /live-medium/live/vmlinuz /live-medium/live/initrd.img /live-medium/live/rootfs.squashfs \
      /mnt/target-data/boot/images/$VER/

Mount the copied image with a persistent overlay, so the next steps write into the real installed root:

$ mount -t squashfs -o loop,ro /mnt/target-data/boot/images/$VER/rootfs.squashfs /mnt/target-sq
$ mount -t overlay overlay -o lowerdir=/mnt/target-sq,upperdir=/mnt/target-data/persist/upper,workdir=/mnt/target-data/persist/work /mnt/target-root

Step 4: basic settings and accounts

$ ROOT=/mnt/target-root
$ ESPUUID=$(blkid -s UUID -o value "${DISK}1")
$ printf '/data/boot  /boot  none  bind  0 0\nUUID=%s  /boot/efi  vfat  umask=0077  0  2\n' "$ESPUUID" > "$ROOT/etc/fstab"
$ echo myhostname > "$ROOT/etc/hostname"
$ ln -sf ../usr/share/zoneinfo/Region/City "$ROOT/etc/localtime"   # e.g. Europe/Lisbon
$ echo LANG=C.UTF-8 > "$ROOT/etc/locale.conf"
$ goget provision --user yourname "$ROOT"    # prompts for your password, creates the account, sudoers, branding
$ chpasswd -R "$ROOT"                         # set the root password, "root:yourpassword"

Step 5: install GRUB

$ grub-install --target=x86_64-efi --efi-directory=/mnt/target-data/boot/efi \
    --boot-directory=/mnt/target-data/boot --removable
$ PARTNUM=1
$ efibootmgr -c -d "$DISK" -p "$PARTNUM" -L systemLinux -l '\EFI\BOOT\BOOTX64.EFI'   # best-effort; fine to fail without efivars
$ DUUID=$(blkid -s UUID -o value "${DISK}2")
$ systemlinux-grubcfg /mnt/target-data/boot "$DUUID"
$ grub-editenv /mnt/target-data/boot/grub/grubenv create
$ grub-set-default --boot-directory=/mnt/target-data/boot "$VER"

Restart and remove the stick. That is the entire install — nothing else runs behind your back.

4. Optional: encrypt with LUKS

To encrypt the data partition, do this before step 2’s mkfs.ext4 in chapter 3:

$ cryptsetup luksFormat "${DISK}2"
$ cryptsetup luksOpen "${DISK}2" systemlinux-data
$ mkfs.ext4 -F -q -L systemLinux /dev/mapper/systemlinux-data

Then use /dev/mapper/systemlinux-data everywhere chapter 3 says ${DISK}2 (mounting, blkid for the data UUID, and so on). At boot, the live initramfs recognises a LUKS data partition from its UUID and prompts for the passphrase before mounting it — there is nothing extra to configure. Keep the passphrase somewhere safe: there is no recovery without it.

5. The fast path: systemlinux-install

Everything in chapters 3–4, asked as plain questions instead of typed by hand:

$ sudo systemlinux-install

It prompts for a whole disk or an existing partition, hostname, username and password, time zone, keyboard layout, and whether to encrypt with LUKS, then runs exactly the steps above. Nothing happens until you confirm the summary it shows first.

6. First boot

GRUB shows for three seconds, then systemLinux starts to a console login (or straight to a root shell if you did not set a login). Your user can use sudo.

7. Installing software

Use goget. Programs go into your own profile, so no sudo is needed:

$ goget find video
$ goget install vlc gimp
$ goget list
$ goget remove gimp
$ goget update                   # newer versions of what you installed
$ goget run neofetch            # run without installing

Prefer a list? Write package names, one per line, to ~/.config/goget/packages and run goget apply: the profile then matches the file exactly. Every change is a generation, so goget rollback undoes it, and goget gc deletes what nothing uses.

8. Updating the system

The system itself updates as a whole image, so an update cannot leave it half-upgraded:

$ goget upgrade --check    # is a newer image available?
$ sudo goget upgrade       # download, verify and install it

The image is downloaded (a broken download resumes), verified against a signed release index and its SHA-256 hashes, and added to the boot menu as a one-time trial. Restart to use it. Your files, accounts, settings and installed programs are not touched.

9. Rolling back

The first boot into a new system image is a trial. If it does not come up, the next boot returns to the previous image automatically. Once the new system has run for a minute, lenine makes it the default. The previous image stays installed and you can pick it by hand in the GRUB menu at startup. Programs installed with goget roll back separately with goget rollback.

10. Recovery

Boot an older image: at the GRUB menu, pick a previous version — every image `goget upgrade` has not yet garbage-collected stays listed and bootable.

Repair a broken install from the live ISO: boot the live medium, then mount and chroot into the installed system the same way the installer assembles it:

$ mkdir -p /mnt/data /mnt/sq /mnt/root
$ mount /dev/sdXN /mnt/data                          # the data partition
$ VER=$(ls /mnt/data/boot/images | sort | tail -1)   # or the version you want to fix
$ mount -t squashfs -o loop,ro /mnt/data/boot/images/$VER/rootfs.squashfs /mnt/sq
$ mount -t overlay overlay -o lowerdir=/mnt/sq,upperdir=/mnt/data/persist/upper,workdir=/mnt/data/persist/work /mnt/root
$ mount --bind /mnt/data /mnt/root/data
$ mount --bind /proc /mnt/root/proc && mount --bind /sys /mnt/root/sys && mount --bind /dev /mnt/root/dev
$ chroot /mnt/root /bin/bash

Fix what needs fixing (reset a password with passwd, edit /etc/fstab, reinstall GRUB with the same command as chapter 3 step 5), then exit and unmount in reverse order before rebooting.

Back up: everything you can lose lives under /persist/upper on the data partition — it is the entire writable layer (your files, accounts, and any changes made outside of goget profiles). Copy it (or just /home and /etc within it) to external storage regularly; system images themselves are always re-downloadable and never need backing up.

11. If something goes wrong

  • The stick does not boot: choose the UEFI entry, write the ISO with dd instead of Ventoy, and check the checksum.
  • No console after boot: use the debug shell entry, or add lenine.verbose=1 to the kernel command line to see lenine’s own log on screen. From a running system, lenine log.
  • No Wi-Fi: a device whose firmware is not in the bundled set will not start. A USB tether or Ethernet always works.
  • Wrong partition wiped: double-check lsblk output before every wipefs/sfdisk command — there is no undo. This is exactly why the fully-manual chapter 3 exists: read each command before you run it.
  • LUKS passphrase not accepted at boot: the live/installed initramfs asks again on the next attempt; a truly lost passphrase means the data partition is unrecoverable by design.
  • An installed system fails to boot: pick the previous image from the GRUB menu, or the debug entry to see messages.

Using lenine

lenine has no configuration to write for a normal boot. These commands control it at runtime (as root).

lenine statusList supervised services (state, PID, restarts, uptime) and any configured timers
lenine log [service]Show lenine’s own log, or a service’s. lenine prints nothing to the terminal; add lenine.verbose=1 to the kernel command line to see its messages on screen
lenine start|stop|restart <service>Control a service (udevd, dbus, NetworkManager, or anything in services.conf)
reboot / poweroff / haltPower commands, also available as lenine reboot|poweroff|halt
/etc/lenine/loginIf this file exists, tty1 asks for a login instead of opening a root shell
/etc/lenine/services.confExtra daemons to supervise, one [after=a,b] [mem=<size>] [cpu=<pct>%] <name> <command> [args] per line. after= waits (up to 10s) for other services to be running first; mem=/cpu= apply a cgroup v2 limit
/etc/lenine/timers.confCommands run on a fixed interval instead of supervised as daemons: <name> every=<duration> <command> [args] (e.g. every=6h), shown in lenine status
HostnameRead from /etc/hostname, defaulting to systemlinux
Logs/run/log/lenine/<name>.log

Honest limits

What this image does not do yet, so nothing surprises you.

  • UEFI only: legacy BIOS boot is not supported.
  • No automatic partition resizing: dual-boot means shrinking Windows or another Linux yourself first, then installing into the freed partition.
  • No Secure Boot yet. LUKS full-disk encryption is available (chapter 4 of the handbook).
  • There is no login screen or lock screen: it is a console system, signed in on tty1 (with optional auto-login).
  • Only English is included. Suspend and lid handling depend on your hardware.
  • Programs from nixpkgs that need hardware-accelerated OpenGL or Vulkan can fall back to software rendering, because they carry their own graphics libraries.
  • The kernel has Intel, AMD and the open NVIDIA (nouveau) graphics drivers, not NVIDIA’s proprietary driver.
  • Atomic, but not sealed: the system image is read-only and swapped as a whole, but changes you make to /etc or /usr yourself are kept in a separate writable layer on top of it (unlike Silverblue’s strictly immutable root).
  • lenine replaces systemd, so software that expects systemd services will not find them.
