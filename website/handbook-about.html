This part of the Handbook installs systemLinux by hand, one command at a time, the way Gentoo and Arch are installed. Nothing is hidden: at the end you know where every file on your new system came from, and you can repair or change any of it later.

What you will do

  1. Download the live ISO, check it and write it to a USB stick.
  2. Boot it. You get a root shell on a running systemLinux.
  3. Get online, to download the stage.
  4. Partition and format the disk you install to.
  5. Extract the stage tarball: the complete system, compilers included.
  6. Configure it: fstab, hostname, time zone, keyboard. Then enter it with chroot.
  7. Put the kernel and initramfs in place.
  8. Install GRUB.
  9. Create your user, unmount and reboot into the new system.

The automatic installer, systemlinux-install, runs exactly these steps after asking a few questions. Use it if you only want a working system; read on if you want to know how it works or need something it does not do.

What systemLinux is

  • x86_64 only, UEFI or legacy BIOS.
  • dinit is the init system and service manager. There is no systemd anywhere; eudev manages devices.
  • glibc and a GNU userland: bash, coreutils, tar, sed, gawk, findutils.
  • The kernel is Ubuntu's newest generic kernel, with its full module tree.
  • Software is built from source with get and the ports tree, a CRUX-style collection of simple recipes. Some ports install a project's own official binaries instead (-bin ports).

Requirements

ProcessorAny x86_64 (64-bit Intel or AMD).
Memory2 GB to install; 4 GB or more to build large packages.
Disk20 GB at least; 40 GB or more if you will build big software (Firefox, LLVM, Qt) from source.
NetworkNeeded to download the stage (about 1 GB) and software. You can also bring the stage on a USB stick.
FirmwareUEFI or legacy BIOS. Turn Secure Boot off: systemLinux's bootloader is not signed.

Conventions in this Handbook

# a command run as root
$ a command run as your normal user
# a comment: do not type it

Text in UPPERCASE inside a command, like /dev/sdX or YOURNAME, is a placeholder: replace it with your own value. The examples use /dev/sda as the disk; yours may be /dev/nvme0n1, /dev/vda (in a virtual machine) or something else, and its partitions are then called /dev/nvme0n1p1, /dev/nvme0n1p2, ...

Partitioning and formatting erase data. Back up everything you care about before chapter 5, and read every command that names a disk twice before you press Enter.
