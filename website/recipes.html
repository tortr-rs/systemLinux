Writing recipes for get

A ports recipe tells get where to download one source archive, how to build it, and which other ports to install first. It is metadata, not a shell script or Makefile: get reads the listed values and runs the selected build and install steps for you.

1. Create the recipe file

From the repository root, make a directory named for the category and package. The recipe file must be named exactly recipe:

mkdir -p ports/dev-apps/hello
${EDITOR:-vi} ports/dev-apps/hello/recipe

Use one key=value entry per line, with each key appearing at most once. Values are plain text; do not use shell commands, variable expansion, or source. Supported archive suffixes are .tar.gz, .tgz, .tar.bz2, .tbz2, .tar.xz, .txz, and .tar.

2. Choose the fields

FieldRequired?Meaning
urlFor a buildable packageDirect URL to one supported source archive. Omit only for a meta-package.
sha256RecommendedExpected lowercase SHA-256 of the downloaded archive. When present, a mismatch stops the build. Recipes without it are not checksum-verified.
requiresWhen dependencies are neededSpace-separated port names, preferably written as category/name. They are installed before this package.
buildNoBuild method: configure (the default), cmake, or meson.
configure_argsNoExtra whitespace-separated arguments passed to the selected configure/setup command. Do not put shell syntax here.

3. Example: configure script and make

This is the normal recipe for an Autotools-style package. The checksum below is a placeholder: replace it with the verified SHA-256 for the exact archive before publishing.

url=https://example.org/hello-1.0.tar.gz
sha256=REPLACE_WITH_VERIFIED_64_CHARACTER_SHA256
build=configure
configure_args=--disable-nls

You can omit build=configure because it is the default. configure_args is optional too.

4. Other build methods

For CMake, set build=cmake. get runs CMake configure, build, and install commands and sets the install prefix:

url=https://example.org/widget-1.0.tar.xz
sha256=REPLACE_WITH_VERIFIED_64_CHARACTER_SHA256
build=cmake
configure_args=-DBUILD_TESTING=OFF

For Meson, use build=meson. get runs Meson setup, compile, and install. For either method, put additional setup options in configure_args.

If the source has no executable ./configure, leave the build method at its default: the source must then contain a Makefile, makefile, or GNUmakefile at its top level. In this case get passes PREFIX to make. If the build needs patches, custom shell steps, or a different build system, it cannot be represented by a plain recipe yet.

5. Dependencies and meta-packages

List dependencies as space-separated names. get recursively installs them first, using the same prefix and staging directory as the requested package. It skips atoms recorded as already installed and stops if it detects a dependency cycle.

url=https://example.org/widget-1.0.tar.gz
requires=dev-libs/libfoo dev-apps/cmake
build=cmake

A meta-package has dependencies but no source URL. It is useful for grouping related packages:

requires=dev-apps/cmake dev-apps/ninja

A recipe needs at least a url or requires. Use valid existing ports for every dependency. Names must use letters, digits, dots, underscores, plus signs, hyphens, and slashes; do not use ...

6. What get does when installing

  1. Downloads the archive into a temporary work directory and checks sha256 if the recipe provides one.
  2. Extracts it and selects the only top-level directory, if there is one. Otherwise it builds from the extracted archive root.
  3. Runs the selected configure/setup step, then compiles the package.
  4. Runs that build system's install step using the selected prefix and optional staging directory.
  5. Removes the temporary directory and records the port as installed, including after a staged install. Use -k on the command line to keep the work directory for debugging.

The default prefix is /usr/local. Installing there normally needs root, so run sudo get category/name. To install for your own account, run get -p "$HOME/.local" category/name instead; the package's build system must honor the chosen prefix.

-d DIR does not change the prefix. It stages the files below DIR while retaining their prefix paths. For example, get -d /tmp/stage category/name with the default prefix places files under /tmp/stage/usr/local; it does not install them into the live /usr/local. A staged port is still recorded as installed in GET_DB, so use a separate database when testing a staged install: GET_DB=/tmp/get-stage-db get -d /tmp/stage category/name.

On a newly installed system, the live ISO's minimal toolset is not enough to compile packages. Install the profiles first, then install the port:

sudo get --profile build-toolchain
sudo get --profile common-build-deps
sudo get dev-apps/cmake
sudo get category/name

Only install lang-runtimes if a package needs Perl, Python, or Go. Some recipes require a compiler or build dependency not covered by these profiles; add that dependency to the recipe's requires.

Profiles are different from ports: get --profile NAME downloads a prebuilt profile archive, while get category/name builds a source archive using its recipe. See the get overview and Handbook for more installation details.

7. Test and share a recipe

  1. Download the exact archive yourself and verify its checksum with sha256sum archive.tar.gz.
  2. Check the URL, build method, required tools, dependencies, and install prefix against the package's upstream instructions.
  3. Test the recipe with get category/name in a system with the needed build profiles installed. Check the installed files, or use GET_DB=/tmp/get-stage-db get -d /tmp/stage category/name to inspect a staged install without marking it in your normal installed-ports database.
  4. Put the recipe at ports/category/name/recipe and submit that file with your ports change.

Recipes are parsed as data and never executed, but a recipe can still make get download and build untrusted source code. Review the upstream source and verify its checksum, especially when installing as root. The installed-atom database does not track files or support uninstalling packages.
