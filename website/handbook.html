The systemLinux Handbook

From the downloaded ISO to an installed system that updates itself. Every command is written out.

Warning: installing erases whichever disk or partition you point it at. Back up first. UEFI only. Legacy BIOS boot is not supported.

1. Make a bootable USB stick

Download the ISO and check it against the SHA-256 on the release page. Then copy it onto a Ventoy stick, or write it straight to a stick (this erases the stick):

sudo dd if=systemLinux-0.2.2-x86_64.iso of=/dev/sdX bs=4M status=progress conv=fsync

Replace /dev/sdX with the stick (check with lsblk). On Windows use Rufus in DD image mode or balenaEtcher.

2. Boot the live system

Restart, open your firmware’s boot menu (usually F12, F10, Esc or F8) and pick the stick’s UEFI entry. The boot menu offers:

  • systemLinux: the normal live session, a root shell on the console.
  • copy to RAM: loads the whole system into memory so you can remove the stick.
  • debug shell: shows every message and stops just before the real system starts. Use it if the normal entry does not work.

Nothing is written to your disks until you follow chapter 3 or run systemlinux-install. Bring up networking first if you need it (nmcli device wifi connect <ssid> password <pass>, or plug in Ethernet).

3. Install to disk, by hand

This is the whole install, one real command at a time. $DISK is a whole disk (e.g. /dev/sda, /dev/nvme0n1); for a dual-boot install into a partition you already freed with GParted or Windows Disk Management, skip straight to the existing partition note under step 2.

Step 1: pick the disk and wipe it

$ lsblk                                 # find your disk; be sure before the next line
$ DISK=/dev/sda
$ wipefs -a -f "$DISK"
$ dd if=/dev/zero of="$DISK" bs=1M count=4

Step 2: partition and format

GPT with a 512 MiB EFI System Partition and one ext4 partition for everything else (system images, GRUB and your files):

$ printf 'label: gpt\n,512M,U\n,,L\n' | sfdisk --wipe always --wipe-partitions always "$DISK"
$ mkfs.vfat -F32 -n EFI "${DISK}1"        # nvme/mmc disks: ${DISK}p1
$ mkfs.ext4 -F -q -L systemLinux "${DISK}2"

Existing partition instead of a whole disk: if you pre-shrank another OS and have a free partition already, set DATADEV=/dev/sdXN to that partition, run only the mkfs.ext4 line above against it, and reuse your existing EFI System Partition (skip the mkfs.vfat line and the whole-disk wipefs/dd in step 1). Then substitute $DATADEV for ${DISK}2 and your existing ESP for ${DISK}1 in every step below.

Step 3: copy the system

$ VER=$(cat /usr/share/systemlinux/image-version)
$ mkdir -p /mnt/target-data /mnt/target-sq /mnt/target-root
$ mount "${DISK}2" /mnt/target-data
$ mkdir -p /mnt/target-data/boot/images/$VER /mnt/target-data/persist/upper \
           /mnt/target-data/persist/work /mnt/target-data/boot/efi
$ mount "${DISK}1" /mnt/target-data/boot/efi
$ cp /live-medium/live/vmlinuz /live-medium/live/initrd.img /live-medium/live/rootfs.squashfs \
      /mnt/target-data/boot/images/$VER/

Mount the copied image with a persistent overlay, so the next steps write into the real installed root:

$ mount -t squashfs -o loop,ro /mnt/target-data/boot/images/$VER/rootfs.squashfs /mnt/target-sq
$ mount -t overlay overlay -o lowerdir=/mnt/target-sq,upperdir=/mnt/target-data/persist/upper,workdir=/mnt/target-data/persist/work /mnt/target-root

Step 4: basic settings and accounts

$ ROOT=/mnt/target-root
$ ESPUUID=$(blkid -s UUID -o value "${DISK}1")
$ printf '/data/boot  /boot  none  bind  0 0\nUUID=%s  /boot/efi  vfat  umask=0077  0  2\n' "$ESPUUID" > "$ROOT/etc/fstab"
$ echo myhostname > "$ROOT/etc/hostname"
$ ln -sf ../usr/share/zoneinfo/Region/City "$ROOT/etc/localtime"   # e.g. Europe/Lisbon
$ echo LANG=C.UTF-8 > "$ROOT/etc/locale.conf"
$ systemlinux-provision --user yourname "$ROOT"    # reads your password from stdin (twice), creates the account, sudoers, branding
$ rm -rf "$ROOT/etc/systemd/system/getty@tty1.service.d"   # ask for a login on tty1 (the live image logs root in)
$ chpasswd -R "$ROOT"                         # set the root password, "root:yourpassword"

Step 5: install GRUB

$ grub-install --target=x86_64-efi --efi-directory=/mnt/target-data/boot/efi \
    --boot-directory=/mnt/target-data/boot --removable
$ PARTNUM=1
$ efibootmgr -c -d "$DISK" -p "$PARTNUM" -L systemLinux -l '\\EFI\\BOOT\\BOOTX64.EFI'   # best-effort; fine to fail without efivars
$ DUUID=$(blkid -s UUID -o value "${DISK}2")
$ systemlinux-grubcfg /mnt/target-data/boot "$DUUID"
$ grub-editenv /mnt/target-data/boot/grub/grubenv create
$ grub-set-default --boot-directory=/mnt/target-data/boot "$VER"

Restart and remove the stick. That’s the whole install. Nothing else runs behind your back.

4. Optional: encrypt with LUKS

To encrypt the data partition, do this before step 2’s mkfs.ext4 in chapter 3:

$ cryptsetup luksFormat "${DISK}2"
$ cryptsetup luksOpen "${DISK}2" systemlinux-data
$ mkfs.ext4 -F -q -L systemLinux /dev/mapper/systemlinux-data

Then use /dev/mapper/systemlinux-data everywhere chapter 3 says ${DISK}2 (mounting, blkid for the data UUID, and so on). At boot, the live initramfs recognises a LUKS data partition from its UUID and prompts for the passphrase before mounting it. There’s nothing extra to configure. Keep the passphrase somewhere safe: there is no recovery without it.

5. The fast path: systemlinux-install

Everything in chapters 3–4, asked as plain questions instead of typed by hand:

$ sudo systemlinux-install

It prompts for a whole disk or an existing partition, hostname, username and password, time zone, keyboard layout, and whether to encrypt with LUKS, then runs exactly the steps above. Nothing happens until you confirm the summary it shows first.

6. First boot

GRUB shows for three seconds, then systemLinux starts to a console login. Your user can use sudo.

7. Installing software

Use get to build software from a source tarball or a named ports recipe. A normal install writes to /usr/local, so use sudo; to install just for your account, choose $HOME/.local as the prefix:

$ sudo get https://ftp.gnu.org/gnu/hello/hello-2.12.tar.gz         # into /usr/local
$ get -p "$HOME/.local" https://ftp.gnu.org/gnu/hello/hello-2.12.tar.gz   # into your home, no sudo

The live ISO has no compiler. Add the build stack from profiles first (downloaded from this image’s release):

$ sudo get --profile build-toolchain
$ sudo get --profile common-build-deps     # cmake, ninja, meson, autotools, pkgconf
$ sudo get --profile lang-runtimes         # Perl, Python, Go
$ validate-build-ready                 # compiles autotools, CMake and Meson test projects

Then build software with sudo get category/name when it installs to /usr/local, or get -p "$HOME/.local" category/name for a user-local install. Full source URLs work too, for example sudo get https://ftp.gnu.org/gnu/coreutils/coreutils-9.5.tar.xz. Use -d /tmp/stage to stage rather than install into the live filesystem. A recipe must explicitly select CMake or Meson; a raw source URL is not automatically detected as either build system. See the recipe guide for exact build and install behavior, or run get --help for all options.

8. Updating the system

There is no in-place updater: to move to a newer systemLinux, write the new ISO to a stick and run systemlinux-install again (onto a new partition, or the same one).

9. Programs you built

Software installed with get goes under /usr/local (or the prefix you chose). Remove it with that project’s own make uninstall, or build it with get -d into a staging directory first to see what it installs.

10. Recovery

Boot an older image: at the GRUB menu, pick a previous version. Every image installed on the disk stays listed and bootable.

Repair a broken install from the live ISO: boot the live medium, then mount and chroot into the installed system the same way the installer assembles it:

$ mkdir -p /mnt/data /mnt/sq /mnt/root
$ mount /dev/sdXN /mnt/data                          # the data partition
$ VER=$(ls /mnt/data/boot/images | sort | tail -1)   # or the version you want to fix
$ mount -t squashfs -o loop,ro /mnt/data/boot/images/$VER/rootfs.squashfs /mnt/sq
$ mount -t overlay overlay -o lowerdir=/mnt/sq,upperdir=/mnt/data/persist/upper,workdir=/mnt/data/persist/work /mnt/root
$ mount --bind /mnt/data /mnt/root/data
$ mount --bind /proc /mnt/root/proc && mount --bind /sys /mnt/root/sys && mount --bind /dev /mnt/root/dev
$ chroot /mnt/root /bin/bash

Fix what needs fixing (reset a password with passwd, edit /etc/fstab, reinstall GRUB with the same command as chapter 3 step 5), then exit and unmount in reverse order before rebooting.

Back up: everything you can lose lives under /persist/upper on the data partition. That’s the entire writable layer (your files, accounts, and any software you built with get). Copy it (or just /home and /etc within it) to external storage regularly; system images themselves are always re-downloadable and never need backing up.

11. If something goes wrong

  • The stick does not boot: choose the UEFI entry, write the ISO with dd instead of Ventoy, and check the checksum.
  • No console after boot: use the debug shell entry, or remove quiet from the kernel command line to see systemd’s boot messages on screen. From a running system, journalctl -b and systemctl --failed.
  • No Wi-Fi: a device whose firmware is not in the bundled set will not start. A USB tether or Ethernet always works.
  • Wrong partition wiped: double-check lsblk output before every wipefs/sfdisk command. There’s no undo. That’s why chapter 3 is written out by hand: read each command before you run it.
  • LUKS passphrase not accepted at boot: the live/installed initramfs asks again on the next attempt; a truly lost passphrase means the data partition is unrecoverable by design.
  • An installed system fails to boot: pick the previous image from the GRUB menu, or the debug entry to see messages.
