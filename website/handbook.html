The systemLinux Handbook

From the downloaded ISO to an installed system. Every command is written out.

Warning: installing erases the disk or partition you choose. Back up first. Both UEFI and legacy BIOS computers are supported.

1. Before you start

  • A 64-bit x86 computer (x86_64), UEFI or legacy BIOS, with at least 2 GB of RAM.
  • At least 10 GB of disk for the system; more if you will build big packages with get.
  • A USB stick of 1 GB or more, or a virtual machine (QEMU, VirtualBox, VMware).
  • A network connection is not needed to install, only to download software afterwards.
  • On UEFI machines, turn Secure Boot off in the firmware settings: the bootloader is not signed.

2. Make a bootable USB stick

Download the ISO from the release page and check it:

$ sha256sum -c systemLinux-0.2.5-x86_64.iso.sha256
systemLinux-0.2.5-x86_64.iso: OK

Copy it onto a Ventoy stick, or write it straight to a stick (this erases the stick):

$ lsblk                                  # find the stick, e.g. /dev/sdb
$ sudo dd if=systemLinux-0.2.5-x86_64.iso of=/dev/sdX bs=4M status=progress conv=fsync

On Windows use Rufus in DD image mode, or balenaEtcher.

Virtual machine: attach the ISO as a CD and give the VM a new empty disk. For example with QEMU:

$ qemu-img create -f qcow2 disk.qcow2 20G
$ qemu-system-x86_64 -enable-kvm -cpu host -m 4G -smp 4 \
    -drive file=disk.qcow2,if=virtio -cdrom systemLinux-0.2.5-x86_64.iso -nic user

3. Boot the live system

Restart, open the firmware’s boot menu (usually F12, F10, F8 or Esc) and pick the stick. The systemLinux menu offers:

  • systemLinux: the normal live system.
  • copy to RAM: loads the whole system into memory, so you can pull the stick out.
  • serial console: also prints to the first serial port (for servers and headless VMs).
  • debug shell: shows every boot message and stops in a shell just before the system starts.

The live system logs you in as root on the console. Nothing is written to your disks until you install.

To get online (only needed for get, not for installing): Ethernet works by itself; for Wi-Fi run

# nmcli device wifi list
# nmcli device wifi connect "NetworkName" password "secret"

4. Install with systemlinux-install

This is the normal way. In the live system run:

# systemlinux-install

It asks, one question at a time:

  1. [d]isk or [p]artition: d erases a whole disk; p installs into one partition and leaves the rest of the disk alone (see chapter 5). It lists your disks first.
  2. The disk, e.g. /dev/sda, /dev/nvme0n1 or /dev/vda in a VM.
  3. Computer name (default systemlinux).
  4. Your username: lowercase letters, digits, - and _. This account can use sudo.
  5. Full name (optional).
  6. Timezone, e.g. Europe/Paris or America/New_York (default UTC).
  7. Console keymap, e.g. us, uk, fr, de.
  8. Password, twice, and whether root gets the same one.
  9. Encrypt with LUKS? If yes, a passphrase, twice. You type it at every boot; a lost passphrase cannot be recovered.

It then shows what it is going to erase and waits until you type yes. Nothing is touched before that. The install takes a few minutes and ends with:

Done. Remove the installation media and reboot.
# reboot

Every question can also be given on the command line, for scripted installs:

# systemlinux-install --disk /dev/sda --host laptop --user alex --tz Europe/Paris --keymap fr [--luks] [--yes]

What a whole-disk install creates: a GPT disk with a 1 MiB BIOS boot partition, a 512 MiB EFI System Partition and one ext4 partition for everything else. GRUB is installed for both UEFI and BIOS, so the disk boots on either kind of machine.

5. Dual-boot next to another system

  1. In the other system, make free space: shrink a partition with Windows Disk Management or GParted, and create a new empty partition of at least 10 GB.
  2. Boot the live system, find that partition with lsblk (check the size), then run systemlinux-install and answer p, then the partition, e.g. /dev/nvme0n1p5.

Only that partition is formatted. On UEFI the existing EFI System Partition is reused (if there is more than one it asks which; or pass --esp /dev/sdXN). On legacy BIOS, GRUB is written to the disk’s boot sectors, so it replaces the other system’s bootloader there.

6. Install by hand

Exactly what systemlinux-install does, for a whole disk on a UEFI machine, one command at a time. Use this if you want to see or change every step. $DISK is the whole disk; on NVMe and MMC disks the partitions are ${DISK}p1, ${DISK}p2, ...

Step 1: partition and format

# lsblk                                 # be sure of the disk before the next lines
# DISK=/dev/sda
# wipefs -a -f "$DISK"
# printf 'label: gpt\n,1M,21686148-6449-6E6F-744E-656564454649\n,512M,U\n,,L\n' | sfdisk --wipe always "$DISK"
# ESP=${DISK}2 DATA=${DISK}3
# mkfs.vfat -F32 -n EFI "$ESP"
# mkfs.ext4 -F -q -L systemLinux "$DATA"

Encryption (optional): instead of the last line, run cryptsetup luksFormat "$DATA", cryptsetup open "$DATA" systemlinux-data, mkfs.ext4 -F -q -L systemLinux /dev/mapper/systemlinux-data, and use /dev/mapper/systemlinux-data as $DATA from here on.

Step 2: copy the system image

The installed system runs from the same compressed image as the live one, with your changes kept in /persist on top.

# VER=$(cat /usr/share/systemlinux/image-version)
# mkdir -p /mnt/data /mnt/sq /mnt/root
# mount "$DATA" /mnt/data
# mkdir -p /mnt/data/boot/images/$VER /mnt/data/boot/efi /mnt/data/persist/upper /mnt/data/persist/work
# mount "$ESP" /mnt/data/boot/efi
# cp /live-medium/live/vmlinuz /live-medium/live/initrd.img /live-medium/live/rootfs.squashfs /mnt/data/boot/images/$VER/
# mount -t squashfs -o loop,ro /mnt/data/boot/images/$VER/rootfs.squashfs /mnt/sq
# mount -t overlay overlay -o lowerdir=/mnt/sq,upperdir=/mnt/data/persist/upper,workdir=/mnt/data/persist/work /mnt/root

Step 3: settings and accounts

# ROOT=/mnt/root
# printf '/data/boot  /boot  none  bind  0 0\nUUID=%s  /boot/efi  vfat  umask=0077  0  2\n' "$(blkid -s UUID -o value "$ESP")" > $ROOT/etc/fstab
# echo mycomputer > $ROOT/etc/hostname
# ln -sf ../usr/share/zoneinfo/Europe/Paris $ROOT/etc/localtime
# echo LANG=C.UTF-8 > $ROOT/etc/locale.conf
# echo KEYMAP=us > $ROOT/etc/vconsole.conf
# systemlinux-provision --user yourname $ROOT    # type your password twice; creates the account and its sudo rights
# echo 'root:rootpassword' | chpasswd -R $ROOT
# sed -i 's/ --autologin root//' $ROOT/etc/dinit.d/getty-tty1   # ask for a login (the live system logs root in)

Step 4: bootloader

# grub-install --target=x86_64-efi --efi-directory=/mnt/data/boot/efi --boot-directory=/mnt/data/boot --removable
# grub-install --target=i386-pc --boot-directory=/mnt/data/boot "$DISK"     # optional: also boot on BIOS
# efibootmgr -c -d "$DISK" -p 2 -L systemLinux -l '\EFI\BOOT\BOOTX64.EFI'    # fine if this fails
# systemlinux-grubcfg /mnt/data/boot "$(blkid -s UUID -o value "$DATA")"
# grub-editenv /mnt/data/boot/grub/grubenv create
# grub-set-default --boot-directory=/mnt/data/boot "$VER"

With LUKS, pass the UUID of the encrypted partition as a third argument to systemlinux-grubcfg (blkid -s UUID -o value /dev/sda3) and the data UUID from /dev/mapper/systemlinux-data as the second.

# umount -R /mnt/root /mnt/sq /mnt/data
# reboot

7. First boot

GRUB waits three seconds, then systemLinux starts to a console login. Log in with your username. Check that your account works:

$ sudo whoami
root
$ su -                                    # root's password; only members of the wheel group may use su

Services are run by dinit (there is no systemd):

$ dinitctl list                           # what is running
$ sudo dinitctl start NetworkManager
$ sudo dinitctl enable NAME                # start NAME at every boot

Connect to the network the same way as in the live system (nmcli). Show off with fastfetch.

8. Installing software

get builds software from the ports tree in /usr/ports. The compilers and build tools are already installed, and dependencies are built first.

$ get search editor                      # find packages
$ get info htop                          # what it is and what it needs
$ sudo get install htop                  # build and install
$ sudo get install firefox-bin           # Mozilla's own build: -bin ports are fast
$ sudo get remove htop                   # uninstall exactly what was installed
$ sudo get sync                          # update the ports tree from the latest release

Packages go into /usr, configuration into /etc. A source tarball without a recipe works too: sudo get install https://ftp.gnu.org/gnu/hello/hello-2.12.2.tar.gz. Browse everything on the Packages page; to add a program, see the packaging guide.

9. Managing installed packages

get list shows what is installed (* marks what you asked for, the rest are dependencies), get files NAME lists a package’s files, and get autoremove removes dependencies nothing needs any more. A package never silently overwrites a file that belongs to another package; an existing file in /etc is kept and the new one is put next to it as FILE.get-new.

A desktop: sway or i3

systemLinux has no login manager or elogind yet: you log in on the console and start your window manager yourself. Firmware first, if your Wi-Fi card or GPU needs it (most laptops do):

$ sudo get install linux-firmware         # then reboot

Sway (Wayland) uses seatd to reach the GPU and keyboard:

$ sudo get install sway foot pipewire wireplumber
$ sudo dinitctl enable seatd
$ mkdir -p ~/.config/sway && cp /etc/sway/config ~/.config/sway/
$ echo 'exec dinit' >> ~/.config/sway/config
$ sway

i3 (X11):

$ sudo get install xorg-server xinit i3 i3status dmenu pipewire wireplumber
$ printf 'exec dinit &\nexec i3\n' > ~/.xinitrc
$ startx

exec dinit starts your own session services: the session D-Bus, and PipeWire with WirePlumber for sound. They are in /etc/dinit.d/user; add your own in ~/.config/dinit.d, and see them with dinitctl list. Your user is in the video, audio and input groups, which seatd, sound and input need.

10. Moving to a new version

There is no in-place upgrade yet. Back up your files (see Recovery), write the new ISO to a stick and install again.

Coming from 0.2.3 or older: those images had wrong file owners, so sudo and su fail with “operation not permitted”. Install 0.2.4 or newer fresh; updating the old install does not fix it.

11. Recovery

Older image: the GRUB menu lists every image on the disk, and a debug entry for each that shows all boot messages.

Repair from the live ISO: boot the stick, then open the installed system:

# mkdir -p /mnt/data /mnt/sq /mnt/root
# mount /dev/sdXN /mnt/data                          # the data partition (LUKS: cryptsetup open it first)
# VER=$(ls /mnt/data/boot/images | sort | tail -1)
# mount -t squashfs -o loop,ro /mnt/data/boot/images/$VER/rootfs.squashfs /mnt/sq
# mount -t overlay overlay -o lowerdir=/mnt/sq,upperdir=/mnt/data/persist/upper,workdir=/mnt/data/persist/work /mnt/root
# for d in dev proc sys; do mount --rbind /$d /mnt/root/$d; mount --make-rslave /mnt/root/$d; done
# chroot /mnt/root /bin/bash

Fix what needs fixing (passwd yourname resets a password), then exit, umount -R /mnt/root and reboot.

Back up: everything that is yours lives in /persist/upper on the data partition: your files, accounts, settings and the software you built. The system images can always be downloaded again.

12. If something goes wrong

  • The stick does not boot: check the checksum, try the stick’s other entry in the firmware menu (UEFI or legacy), turn Secure Boot off, or write it with dd instead of Ventoy.
  • Boot stops or the screen stays black: pick the debug entry to see the messages. In the GRUB menu you can press e and remove quiet too.
  • “Operation not permitted” with sudo or su: you are on an install from 0.2.3 or older; install 0.2.4 or newer fresh. su also refuses users who are not in the wheel group (id shows your groups).
  • No Wi-Fi: a card whose firmware is not bundled will not start. Ethernet or a USB phone tether always work.
  • The installer stops with “has mounted partitions”: unmount them (umount /dev/sdXN) and run it again.
  • Wrong disk: there is no undo. Read the lsblk output and the installer’s summary before typing yes.
  • A port fails to build: run it again with sudo get install -k NAME to keep the build directory, and open an issue with the error.
