Services

systemd starts everything; there is nothing to configure for a normal boot. The usual tools control it (as root).

systemctl status [unit]What is running, and what failed (systemctl --failed)
journalctl -b [-u unit]This boot’s log, or one service’s
systemctl start|stop|restart <unit>Control a service: NetworkManager, …
reboot / poweroff / haltPower commands
/etc/systemd/system/The base image’s own units; add yours here and systemctl enable them
ConsoleThe live ISO logs root in on tty1; an installed system asks for a login. Add console=ttyS0 to the kernel command line for a serial login
HostnameRead from /etc/hostname (systemlinux on the live ISO)

What doesn't work yet

Known gaps. If one of these gets in your way, open an issue, or better, help fix it.

  • UEFI only: legacy BIOS boot is not supported.
  • No automatic partition resizing: dual-boot means shrinking Windows or another Linux yourself first, then installing into the freed partition.
  • No Secure Boot yet. LUKS full-disk encryption is available (chapter 4 of the handbook).
  • There’s no graphical login or lock screen. It’s a console system: you log in on tty1.
  • Only English is included. Suspend and lid handling depend on your hardware.
  • The kernel has Intel, AMD and the open NVIDIA (nouveau) graphics drivers, not NVIDIA’s proprietary driver.
  • The system image is read-only; changes you make to /etc or /usr yourself are kept in a separate writable layer on top of it.
