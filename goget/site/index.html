Build from source.
Fetch a binary only when it's proven to run.

goget gets a repo's source — preferring a straight HTTP download of the latest tagged release's source archive over a full git clone, falling back to git when there's no tag — and builds it with whatever build system it actually uses: CMake, Make, or Autotools. If there's no source build available, it can fall back to a GitHub release binary, but only after checking architecture, musl-vs-glibc, and the exact glibc version it needs against your host. A binary that fails any check is treated as if it doesn't exist.

One spec, four shapes

Full URL, SSH remote, bare host/owner/repo, or just the name — goget parses whichever one you happen to have on hand.

  • fastfetchbare short name — searched across GitHub, GitLab, and Codeberg, sorted by stars
  • antirez/kiloowner/repo, assumed to be on github.com
  • gitlab.com/owner/repoexplicit host/owner/repo, any of the three hosts
  • git@github.com:owner/repo.gitSSH remote, scp-style or ssh://

Picking the right binary out of a real release

Release tarballs are messy: multiple platforms, sometimes a binary and a same-named completion script sitting side by side. goget filters for architecture and OS by name, then disambiguates what's left.

1. filter

Right OS, right arch

Matches uname -m against the asset name and drops anything for macOS, Windows, or a BSD before it's even downloaded.

2. disambiguate

bin/ beats loose files

When an archive has two files with the same name (a binary and a bash-completion script, say), the one under a bin/ path wins, then the one with the executable bit set.

3. verify

Checksum if there is one

A .sha256/checksums.txt-style file is verified if present — warns and continues if absent, hard-fails on a mismatch.

Compatibility isn't optional

A release existing isn't the same as it running. Every candidate binary goes through the same checks before it's trusted.

  • ✓
    Architecturethe asset's declared architecture must match this host's uname -m
  • ✓
    musl vs glibca musl binary on a glibc host (or vice versa) is rejected outright, regardless of version
  • ✓
    glibc versionthe binary's minimum required glibc (from its GLIBC_x.y symbol versions) can't exceed what the host actually has
  • ✕
    Anything that failsis treated as if no release exists at all — goget offers to build from source instead of installing something broken

goget.conf

One small config file: a host allow-list and USE flags that turn into real build options.

# ~/.config/goget/goget.conf
pkg.repos{github.on gitlab.on codeberg.on}

# global default for every package
pkg.USE{wayland.on x11.on pulseaudio.off}

# per-package override beats the global block above
pkg.fastfetch.USE{pulseaudio.on}
USE flagbuild option
wayland-DENABLE_WAYLAND
x11-DENABLE_XCB_RANDR and -DENABLE_XRANDR
pulseaudio-DENABLE_PULSE

If a package resolves to a host you've disabled, goget asks once — Once proceeds without touching the file, Always flips it permanently, Cancel exits clean. It only ever applies to the package you actually asked for.

Building goget itself

Go, standard library only — no third-party modules, no libcurl, no libarchive. CGO_ENABLED=0 means the result is a genuinely static binary.

  1. git clone https://github.com/tortr-rs/goget.git

    Clone the source.

  2. make

    Runs CGO_ENABLED=0 go build. Nothing to fetch — net/http, encoding/json, archive/tar+zip, and debug/elf cover everything a source-first package manager needs.

  3. sudo make install

    Installs to /usr/local/bin/goget.

  4. goget build <repo>

    Point it at anything and see what it finds.

goget is source-first by design: a working build beats a maybe-compatible binary.
